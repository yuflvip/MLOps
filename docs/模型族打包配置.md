# 模型族打包配置（第一阶段）

本阶段仅管理模型族的打包配置，不执行打包、FTP 上传或权重包列表管理。

## 使用

在模型族新建/编辑抽屉的“打包配置”中维护：

- 直接使用模型族标识作为打包标识，不设置独立的 `package_key`。
- 模型软链接主名称：例如 `vehicle_base_classifier`，不输入后缀。692、530 自动生成 `.bin`，x86、3403svp、3403nnn、rk3588 自动生成 `.weights`。
- 填写模型软链接主名称后自动生成 cfg、names 链接名称（主名称加 `.cfg` / `.names`），也可继续手动调整。
- cfg、names 包内文件名固定为 `模型族标识.cfg`、`模型族标识.names`，只读展示；UTF-8 原文支持导入、编辑、下载。导入后需要保存模型族才会持久化。

配置可以逐步填写，尚未准备打包的模型族无需填写。内容作为模型族默认配置，后续打包时应校验所选模型版本对应的类别和顺序。当前保存会替换该模型族配置，不包含独立文件版本历史。

## 接口与存储

现有 `/projects` 创建、修改、详情和列表接口增加 `packaging` 对象。配置保存在 `projects.packaging_json`；旧记录为空时返回默认配置。旧客户端更新时不传 `packaging` 会保留已有配置，传 `{}` 会清空为默认值。

```json
{
  "packaging": {
    "model_links": {
      "x86": "vehicle_base_classifier.weights",
      "692": "vehicle_base_classifier.bin",
      "530": "vehicle_base_classifier.bin",
      "3403svp": "vehicle_base_classifier.weights",
      "3403nnn": "vehicle_base_classifier.weights",
      "rk3588": "vehicle_base_classifier.weights"
    },
    "cfg_link": "vehicle_base_classifier.cfg",
    "names_link": "vehicle_base_classifier.names",
    "cfg_filename": "classify_vehiclebase.cfg",
    "cfg_content": "[yolo]\nclass_num=2\n",
    "names_filename": "classify_vehiclebase.names",
    "names_content": "car\nbus\n"
  }
}
```

后端校验平台、链接后缀、公共主名称和文件名。提供任意一个平台的有效链接时，会自动补全其余平台。cfg/names 内容分别限制为 1,048,576 字符，界面导入限制为 1 MiB；换行统一保存为 LF。

## 部署

后端启动时自动检查并升级有 Alembic 版本记录的数据库；迁移成功后才提供服务，无需手工执行命令。SQLite 使用写事务串行化多个进程的启动迁移。新空数据库自动建表并记录最新版本；完整但未记录版本的当前结构可自动登记，不完整的无版本数据库会停止启动，避免错误标记版本。

运行环境须安装项目声明的 Alembic 依赖。迁移失败会回滚并停止启动，在日志中记录错误。

全局配置 `backend/config/app.yaml`：

```yaml
model_packaging:
  deploy_dir: "/opt/AII/YoloModel"
```

模型族表单不设置部署目录。

## 后续打包约定

- 包名：`weight_{模型族标识}_{platform}_{date}.tgz`。
- 平台：`x86 | 692 | 530 | 3403svp | 3403nnn | rk3588`。
- 日期/版本默认训练结束时间的 `yyyyMMdd00`，由后续打包功能从实验计算，模型族不存固定日期。
- 压缩、同名包处理、FTP 上传、权重包列表及历史配置快照在下一阶段实现。

模型族标识修改后，文件名同步更新；导入文件保留内容，不采用上传文件的原始名称。已有数据库启动时自动清理旧 package_key 并更新派生文件名，保留 cfg/names 原文及链接配置。
